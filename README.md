# АвтоКонтроль — ГИБДД Красноград

PHP + MySQL/MariaDB без фреймворков. Интерфейс в тёмной сине-графитовой теме, адаптивен для компьютера и телефона.

## Возможности

- Поиск по госномеру, VIN, марке и модели.
- Карточка автомобиля с характеристиками, фото и лентой истории.
- Регистрация транспортного средства сотрудником; свободный госномер генерируется автоматически с кодом региона **200** (формат `А123ВС200`).
- Загрузка фотографий JPG/PNG/WEBP до 5 МБ.
- Личный кабинет владельца со своими автомобилями и штрафами.
- Оформление штрафов сотрудником ГИБДД и отправка в «Капитал-Стандарт» через API.
- Повторная отправка начисления при ошибке. При повторе сохраняется тот же `external_ref`, чтобы банк мог применить защиту от дублей.
- Роли: `user` (владелец), `inspector` (инспектор), `officer` (сотрудник ГИБДД), `admin` (администратор).
- Администрирование ролей, журнал API, CSRF-защита, PDO prepared statements, `password_hash`, MIME-проверка загружаемых фото.

## Требования

- PHP 8.1+; расширения PDO MySQL, Fileinfo, JSON, Mbstring. Для исходящего HTTP рекомендовано расширение cURL.
- MySQL 5.7+/8.x или актуальная MariaDB.
- Веб-сервер Apache/Nginx с корнем сайта на каталоге проекта; разрешение PHP на запись в `uploads/vehicles`.

## Установка через XAMPP

1. Распакуйте каталог `autocontrol` в `C:\xampp\htdocs\autocontrol`.
2. Запустите Apache и MySQL в панели XAMPP.
3. Откройте phpMyAdmin и импортируйте файл `schema.sql`. Он создаёт базу `autocontrol` и таблицы.
4. Проверьте настройки БД в `config.php` (по умолчанию `root` без пароля, как в стандартном локальном XAMPP). Для другой среды скопируйте `config.local.php.example` в `config.local.php` и измените параметры.
5. Убедитесь, что `uploads/vehicles` доступен PHP на запись.
6. Откройте `http://localhost/autocontrol/`.
7. Зарегистрируйте свой аккаунт. **Первому пользователю нужно назначить роль `admin` вручную** (см. ниже).

### Назначить администратора

После регистрации первого пользователя выполните в phpMyAdmin, заменив email на свой:

```sql
USE autocontrol;
UPDATE users SET role='admin' WHERE email='your-email@example.com';
```

Выйдите и войдите заново, чтобы обновить данные роли в сессии. После этого роли можно менять на странице «Пользователи».

## Подключение банка «Капитал-Стандарт»

Интеграция реализована на серверной стороне. Браузер не получает API-ключ.

1. Адрес API банка уже указан в настройках по умолчанию: `http://26.155.57.105:7777/api.php`. Если публичный адрес банка изменится, задайте переменную окружения `BANK_API_URL` или измените `api_url` в `config.local.php`.
2. Скопируйте `config.local.php.example` в `config.local.php`.
3. Впишите НОВЫЙ действующий ключ в массив `bank` (старый ключ, отправленный в чат, рекомендуется отозвать):

```php
'bank' => [
    'api_url' => 'http://26.155.57.105:7777/api.php',
    'api_key' => 'ЗДЕСЬ_НОВЫЙ_КЛЮЧ',
    'timeout' => 12,
],
```

4. В штраф передаются JSON-поля `action=issue_fine`, `customer_email`, `external_ref`, `title`, `amount`, `details`, `vehicle_plate`, `due_date`; ключ передаётся заголовком `X-API-Key`.
5. Email владельца в карточке автомобиля должен совпадать с email, по которому клиент зарегистрирован в банке.
6. Проверьте успешную отправку тестовым штрафом на тестовом аккаунте. В разделе «Интеграция с банком» виден журнал ответа. При ошибке можно нажать «Повторить» в реестре штрафов.

**Важно по безопасности:** указанный адрес работает по обычному HTTP. Заголовок `X-API-Key` при таком подключении может передаваться без шифрования. Для реального использования сначала настройте HTTPS на стороне банка и замените URL на `https://.../api.php`. Ключ, отправленный в чат/показанный на скриншоте, следует считать раскрытым: отзовите его и создайте новый. Новый ключ храните только в `config.local.php` или переменной окружения `BANK_API_KEY`; в ZIP секрет не зашит.

## Поведение API и повторные запросы

- Локальная запись о штрафе сохраняется до вызова банка.
- Успешная передача помечается `sent`, ошибка — `error`, отсутствие настроек — `not_configured`.
- При повторах используется прежний `external_ref`. Реальный банк должен поддерживать идемпотентность по этому полю, как описано в его API.
- Автоматические периодические платежи, синхронизация статуса оплаты и отмена уже отправленных начислений требуют дополнительных действий и webhook/API-методов на стороне банка; текущая интеграция передаёт начисления и показывает результат запроса.


## Продажа автомобилей между пользователями

- Владелец выставляет свой автомобиль с ценой и разрешёнными способами оплаты: наличными и/или переводом со счёта «Капитал-Стандарт».
- Покупатель отправляет заявку. Автомобиль не переходит к нему автоматически: сделку должен принять продавец.
- Для наличных продавец обязан отметить подтверждение фактического получения наличных. После этого меняется владелец в реестре.
- Для оплаты по счёту продавец принимает заявку, банк атомарно списывает цену с выбранного активного счёта покупателя и зачисляет её на счёт продавца. Реестр меняет собственника только после подтверждённого ответа банка.
- Повторные банковские запросы используют стабильный внешний номер сделки и ключ идемпотентности: повтор не должен списать оплату дважды. Если связь с банком прервётся во время перевода, объявление останется зарезервированным до повторной проверки этой же заявки.

### Установка обновления продажи автомобилей

Для существующей базы импортируйте в phpMyAdmin файл `migrations/20261015_vehicle_marketplace.sql` после выбора базы `autocontrol`. Для новой установки таблицы уже включены в `schema.sql`.

### API банка для покупки автомобиля

В репозитории «Капитал-Стандарт» доступен партнёрский endpoint `php_bank_app/public/api.php`. Разверните его на том же домене/DocumentRoot, где работает банковское приложение, и задайте на сервере банка переменную окружения `BANK_PARTNER_API_KEY`. В `capital_gibdd/config.local.php` значение `bank.api_key` должно совпадать с этим секретом; не помещайте ключ в клиентский JavaScript или публичные файлы. На стороне банка также должна быть применена миграция `database/migrations/20261012_gibdd_integration.sql`, так как API использует `external_bill_links` для защиты от дублирования штрафов.

Публичное развёртывание требует HTTPS и одинакового общего секрета на обеих сторонах. До включения банковской оплаты проверьте на тестовых аккаунтах покупателя и продавца: список счетов, перевод, отказ при нехватке средств и повторный запрос с тем же номером сделки.

## Замечания для развёртывания

Это стартовая система для вашего RP/демо-проекта, а не официальный реестр МВД и не подключение к государственным базам. Для публичного размещения настройте HTTPS, резервные копии, логирование доступа и политику хранения персональных данных. Не используйте реальные персональные данные без законного основания.
